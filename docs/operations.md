# Operations runbooks

Prod (branch `release`) is the only hosted environment since the dev/staging environment was retired on 2026-11-22 (ADR-0012); runbooks marked "dev only" need a recreated dev environment ([deployment.md](deployment.md) §1–2 with `ZIDCMS_ENV=dev`). Scripts that call a deployed environment read `ZIDCMS_ENV_FILE=.local/secrets/<env>.env`; without it the RPC scripts (`poc:gas`, `setup:sheet`) use `apps/admin/.env.local`, and `check:deployed`/`smoke:deployed` refuse to run.

| ID  | Situation                                           | Procedure                                                                                                                                                                                                                                                                                                                                                                                                  |
| --- | --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | Bad content live                                    | Admin → _Publikasi & Snapshot_ → _Rollback_ on the last good version (creates a new version). If the admin is down: Vercel dashboard → web project → _Instant Rollback_ to the previous deployment.                                                                                                                                                                                                        |
| R2  | Publish job stuck                                   | Open _/publish_ — polling resumes the job (step claims expire after 60–240 s, job leases after 10 min). Deploy/verify steps fail by themselves after 15 / 3 min. If the job row is inconsistent, mark it failed: `pnpm poc:gas publish.updateJob '{"id":"<job>","from_state":"<state>","to_state":"failed","fields":{"error_code":"INTERNAL_ERROR","error_message":"manual"}}'`, then start a new publish. |
| R3  | Rotate HMAC secret                                  | Generate a new secret → set GAS Script Property `HMAC_SECRET` → set Vercel `GAS_HMAC_SECRET` → redeploy admin. Expect `SIGNATURE_INVALID` for a short window (dual-secret rotation is P2).                                                                                                                                                                                                                 |
| R4  | Redeploy GAS                                        | [deployment.md §1](deployment.md); verify with `ZIDCMS_ENV_FILE=.local/secrets/<env>.env pnpm poc:gas`; check version count < 200.                                                                                                                                                                                                                                                                         |
| R5  | Restore spreadsheet                                 | Drive version history (or the copy taken before a schema change) → `pnpm setup:sheet` (prod refuses `system.setup` once installed; a restored prod sheet does not need it) → `system.health` → republish.                                                                                                                                                                                                  |
| R6  | Remove an admin                                     | Remove from `ADMIN_EMAILS`, redeploy admin, rotate `AUTH_SECRET` to invalidate sessions.                                                                                                                                                                                                                                                                                                                   |
| R7  | Leaked GitHub token                                 | Revoke the PAT, create a new one, update the env files and both admin projects (`pnpm exec tsx scripts/vercel-env-sync.ts prod`; the retired dev environment used the same PAT), inspect repo history for unexpected commits, roll back via R1 if needed.                                                                                                                                                  |
| R8  | Quota exhaustion                                    | Apps Script executions dashboard; quotas reset 24 h after first use; reduce publish frequency; record numbers in `docs/benchmarks.md`.                                                                                                                                                                                                                                                                     |
| R9  | Demonstrate a failed build (TC-PUB-07)              | `pnpm build-switch on` sets `ZIDCMS_FAIL_BUILD=1` on the dev web project, so the next build exits early with a clear message. Publish something, watch the job end in `failed`/`DEPLOY_FAILED` while the old version stays live, then **always** run `pnpm build-switch off`. Dev only: the dev web project it targets was deleted (ADR-0012), so this needs a recreated dev web project.                  |
| R10 | Check validation of manual sheet edits (TC-DATA-05) | In the dev spreadsheet change one cell of a test row to an invalid value (e.g. `status` = `banana`). `GET /api/health` (or `pnpm poc:gas system.health`) must report the row under `invalid_rows`, and lists/snapshots must exclude it. Restore the value afterwards. Dev only (needs a recreated dev spreadsheet, ADR-0012).                                                                              |
| R11 | Promote code to prod                                | [deployment.md §3](deployment.md): CI green and emulator-stack workflows (`integration.yml`, `e2e.yml`) green on `main` (no staging, ADR-0012) → merge `main` into `release` (owner approval; never the reverse) → redeploy the prod script if Apps Script changed → `ZIDCMS_ENV_FILE=.local/secrets/prod.env pnpm check:deployed`.                                                                        |
| R12 | Verify an environment after an incident or rollback | `ZIDCMS_ENV_FILE=.local/secrets/prod.env pnpm check:deployed` (auth matrix, Origin, headers, 404, robots/sitemap, snapshot privacy, no web functions). For a full publish path run `… pnpm smoke:deployed` (sacrificial post: publish → update → rollback → unpublish; costs ~4–8 deployments).                                                                                                            |

## Logs

- Admin: JSON lines `{ level, msg, at, requestId, action, code, … }` in Vercel function logs; secrets and e-mail local parts are redacted. `LOG_LEVEL=debug` adds per-RPC timings.
- Apps Script: `console.log` JSON in the executions dashboard. Security rejections log `code`, `reason`, `requestId` only.
- `requestId` is generated by the admin and propagated in the RPC envelope and `AuditLog`.

## Health

`GET /api/health` (admin session) returns admin environment, publish target, and `system.health` (environment, schema version, row counts, invalid rows from manual edits). It reads every sheet, so expect about 11 s or more.
